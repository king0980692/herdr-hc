hc バックエンド版は **hc のデフォルト共有マシン登録簿**を読み取り、別の SSH カタログへコピーしません。1 つの Herdr ウィンドウで、各マシンのワークスペースと Local を切り替えられます。**Herdr はローカルで描画し、hc がリモートプログラム、ターミナル状態、明示的に報告されたエージェント状態を所有します。** 保存済みマシンのセットアップは、リモート Herdr のインストール、起動、置き換えを行わず、リモート Herdr 経由で描画することもありません。

接続は独立した 2 段階です。クライアントはローカルの表示ホストに接続し、そのホストが SSH 越しに hc に接続します。表示用接続が正常でも、hc に到達できるとは限りません。利用できないペインは保存済みの識別情報とレイアウトを保持し、代替シェルには置き換わりません。

## 共有 hc マシン

共通の一覧は hc（`hc machine ls --json`）で確認・管理します。Herdr はペイン描画とは独立してバックグラウンド更新します。名前は表示用です。接続先は恒久的な所有 core ID と登録簿 core ID で識別し、改名でバインディングは変わりません。所有者、登録簿、経路の置換で古いレイアウトを黙って引き継ぐこともありません。

保存済みネイティブレイアウトがないマシンでは、既存の **live な所有者ローカルプログラムを各 1 タブ**として表示します。新しいシェルは起動せず、他アプリの PTY やレイアウトも取り込みません。保存済みネイティブレイアウトは変更せず、終了履歴を live として取り込みません。空のリモート接続先は、明示的にワークスペースを作るまで空のままです。明示的なペイン閉鎖はその正確な共有プログラムを終了しますが、Herdr の終了や接続断は表示の分離だけです。

直接 SSH マシンをサポートします。プロバイダーコマンド（`via`）は SSH と読み替えず、安全に拒否します。状態、入力の主導権、サイズの動作はインストール済み hc と互換である必要があり、接続成功だけでは複数ビューの検証にはなりません。

以下の保存プロファイル用コマンドは、並行配置の `--hc-path` を含む **明示的な旧式・独自接続先**向けです。共有登録簿にあるマシンには不要で、これらのコマンドが共有登録簿を編集することもありません。

## 接続前の確認

最初に通常の SSH 接続を確認します:

```bash
ssh workbox
```

`workbox` は SSH config のエイリアスでも構いません。`ssh://you@server:2222` のような接続先も使えます。マシンを追加する前に、接続先に互換性のある `hc` をインストールしてください。Herdr は hc API を確認するだけで、リモート Herdr のインストーラーを提供したり、hc を黙って更新したりしません。

現在の接続先での起動処理には POSIX シェルと接続先の `/usr/bin/env` を使います。macOS と Linux の起動経路はネイティブ smoke テストで確認していますが、Windows の起動は未検証です。認証とホスト鍵の承認は OpenSSH が扱います。パスフレーズ付きの鍵は、バックグラウンド接続が必要になる前に `ssh-add` で読み込んでください。

## マシンを追加する

```bash
herdr machine add workbox
herdr machine add workbox --remote-session agents --label "Build machine"
# 任意：接続先に並存する hc 実行ファイルを選び、通常の UI を使います。
herdr machine add workbox --remote-session agents --hc-path /home/user/.local/opt/hc/bin/hc
herdr
```

`--hc-path` は任意の絶対**接続先ローカル実行ファイルパス**であり、シェルコマンドやクライアント側のパスではありません。省略時は接続先 PATH の `hc` を使います。保存されたパスは状態確認、再接続、TUI で共通して使われます。指定ファイルが存在しない場合や非互換の場合、別の hc へフォールバックしません。このフィールドには新しいローカル Herdr が必要です。同じカタログを共有する前に、古いクライアントとプレゼンテーションホストを更新してください。

`--remote-session` はリモート Herdr ではなく、**接続先の hc セッション**を選びます。省略時は `default` を使い、リモート Herdr のセッション検出は行いません。デフォルトラベルはホスト名で、名前付きセッションでは `host/session` です。名前が使用済みなら `--label` を指定してください。

セットアップは SSH 越しにインストール済み hc を確認してから、プロファイルを保存します。シェルの作成、任意の既存 hc ターミナルの取り込み、プログラムの再起動は行いません。新しいプロファイルのローカル表示は空で、ワークスペースを明示的に作成するまでプログラムは起動しません。再度開く場合も、保存済み hc バインディングを持つターミナルだけを復元します。

各プロファイルは不透明な ID と、`hc-<profile-id>` という独立したローカル表示セッションを持ちます。表示ホストはクライアント終了後も動き続けられます。クライアントを閉じる操作はデタッチであり、接続先のプログラムを終了しません。

`herdr` で UI を開きます。有効なマシンは既存のマシンサイドバーに表示され、それぞれ独立して接続します。別のマシンを選択しても、プログラムの移動や再起動は行いません。

## マシンを切り替える

サイドバーでマシンまたはそのワークスペースを選びます。選択中のマシンがペイン入力とサイズ更新を受け取ります。ほかの接続済みマシンは、非表示ペインの画面を送信せずにメタデータを更新し続けます。

マシン横の矢印で、マシンを切り替えずにワークスペース一覧を折りたためます。キーボードでは `prefix+w` を押し、ワークスペースをハイライトして Enter で確定します。Esc またはプレフィックスキーでキャンセルします。ハイライトしただけでは、ペイン、タブ、ワークスペース、カスタムコマンドのショートカットの対象は変わりません。

Local は保存済みマシンの障害から独立しています。応答のない接続先が、使用中マシンから選択を奪うことはありません。複数クライアントは引き続き別々のタブを選択できます。[クライアントとサーバー](/ja/docs/concepts/)を参照してください。

## 安全な再接続と終了

接続先との通信が切れても、ビューアーをデタッチするだけで、プログラムは停止しません。Herdr は通信を再接続し、各ターミナルの**恒久的な hc core ID と正規ターミナルアドレス**を使って非同期に再アタッチします。公開されるワークスペース、タブ、ペイン ID は表示側の識別情報であり、hc アドレスではありません。

復旧時に、結果が不明な `terminal.run` の再試行、入力の再送、エージェントの再開、従来の PTY のインポートは行いません。接続先内のアドレスが同じ別ターミナルに差し替えることもありません。ターミナルの欠落、core の不一致、不正なバインディング、オフラインの場合は、元のレイアウトとバインディングを保持して利用不可とします。hc に状態を明示的に報告していないプログラムは不明のままで、画面やローカル PID から推測しません。

接続先への再試行は 500 ミリ秒から始まり、最大 30 秒までバックオフします。正常な接続が 1 分続くとリセットします。アタッチ試行には別の並行数制限があり、キャンセルできます。クライアントと表示ホスト間の既存の再接続方針は、この再試行ループとは独立しています。

ペイン、タブ、ワークスペース、ポップアップを明示的に閉じると、そのバインディングが指す hc プログラムを終了できます。hc が終了、または有効な不在確認を返すまで、レイアウトとバインディングは削除しません。オフラインや結果不明の終了要求では両方を保持し、失敗を報告します。最後のペインを閉じても代替シェルは作成しません。

## 名前の変更、無効化、削除

ラベルやホスト名から推測せず、カタログからプロファイル ID を取得してください:

```bash
herdr machine list
herdr machine list --json
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id>
```

名前の変更はラベルを更新するだけで、プログラムの識別情報は変えません。無効化はプロファイルを残し、削除はプロファイルを忘れます。どちらもその接続先をデタッチするだけで、hc プログラムを終了せず、ほかのマシンにも影響しません。選択中のマシンを削除または無効化すると Local に戻り、Local が利用できなければその利用不可・再接続状態を表示します。無関係なリモートを選ぶことはありません。

接続経路（同じ core に到達する場合も hc 実行ファイルのパスを含みます）または恒久的な core ID が変わると、古いローカル接続先ホストは退役します。新しいホストは新しいインスタンス識別子を持ち、古い要求は置き換え先へ転送せずに拒否します。接続先を変更しても、古い `t1` バインディングが別 core の `t1` を操作する権限になることはありません。

## 接続の問題

```bash
herdr machine status [<label-or-id>] [--json]
herdr machine reconnect <label-or-id>
```

Status はインストール済み hc を非対話式で確認します。Reconnect は対応するネイティブ SSH 認証を完了して hc を確認しますが、Herdr や hc のインストール・更新は行いません。バックグラウンド接続には既知のホスト鍵が必要で、認証やホスト鍵のプロンプトには回答しません。有効な場合は既存の管理対象 SSH 認証接続を再利用します。読み取り専用接続の失敗後の修復は、古いことが証明され、現在の操作に属する管理対象リスナーだけを退役させます。既存の SSH セッションや hc プログラムは停止しません。エラー・再接続バッジをクリックすると再試行し、現在の通知を確認できます。ほかのマシンは利用できます。

hc がない、または非互換の場合は、接続先の hc を明示的に更新してください。ローカル表示ホストに必要な API がなければ、**ローカル Herdr** を更新します。保存済み hc 接続を修復するためにリモート Herdr サーバーを置き換えないでください。ローカル表示ホストを停止してもビューアーがデタッチするだけで、hc プログラムは接続先に残ります。

カタログが読めない、または不正な場合は、変更後の経路を有効化する前に修正する必要があります。既存のクライアント接続は、それぞれ独立したライフサイクルを保ちます。プロファイルのエラーは、無関係なサーバーを停止する権限にはなりません。

## 接続先のパスと利用可能な操作

暗黙のシェルは接続先の `SHELL`、未設定なら `/bin/sh` を使い、クライアントのシェルパスは使いません。デフォルトのホーム・現在のディレクトリは接続先で解決し、ディレクトリ追従には hc が報告した cwd を使います。明示的なパスと argv は接続先の値であり、クライアントのホームでは展開しません。

ターミナルコマンドは hc 経由で実行します。実行ファイル、設定、コマンドプラグイン、シークレットを接続先へコピーしません。接続先のプログラムには、ローカル表示ホストの API ソケット、実行ファイルパス、ペイン識別情報、ローカル SSH-agent プロキシのパスを渡しません。接続先自身の SSH-agent 環境は維持します。接続先の実行環境はそこでの `hc` で操作するか、ローカルクライアントからマシン指定の Herdr コマンドを使ってください。コマンドがなければエラーを表示します。このアダプターでは接続先の Git 検出と worktree ファイルシステム操作は未対応で、拒否または省略します。同名のローカルパスを操作する代替動作はありません。

ワークスペース、タブ、ペイン ID とエージェント名は表示ホストごとに独立しています。2 つのプロファイルに同じ `w1:p1` が存在する場合があります。UI でマシンを選択しても、既存ペイン内の CLI の接続先は変わりません。自動化では各コマンドに同じマシンプレフィックスを付けてください:

```bash
herdr --machine <label-or-id> agent list
herdr --machine <label-or-id> workspace list
```

CLI に開いている TUI は不要です。保存済みプロファイルからローカル接続先ホストを解決し、そのインスタンスに後続の要求を固定します。解決後にホストが再起動した場合はエラーであり、接続先の再検出や変更要求の再実行を許可するものではありません。

## 保存データと従来のプログラム

カタログにはプロファイル ID、ラベル、SSH 接続先、hc セッション、有効状態だけを保存します。パスワード、秘密鍵、SSH 制御ソケットは保存しません。バインディングと表示レイアウトは別に保存します。Snapshot バージョン 4 により、古い Herdr が hc バインディングを従来の再起動指示として扱うのを防ぎます。

従来の Herdr プログラムは**インポート、再起動、取り込みを行いません**。hc には公開された live-PTY インポート API がありません。明示的に切り替えを手配するまでは、古いサーバーを動かし続けてください。保存済みプロファイルの変更は、古い Herdr ターミナルの移行にはなりません。live PTY handoff と、従来のプロセス管理経由での hc worktree 削除は未対応です。
