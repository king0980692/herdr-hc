title: エージェントに Herdr 対応を追加する
description: クライアント側 hook や自動プロセス再開に頼らず、接続先 hc と OSC 7501 で状態を報告します。
---

hc ペインには **hc の Program Status Protocol、OSC 7501** で報告します。hc が事実を所有し、Herdr が表示と、ライブの報告による待機・通知を担当します。状態判定に Herdr のプロセス名や画面ルールは不要です。

従来の Herdr CLI／ソケット報告と resume 統合は別の旧契約です。hc ペインは `pane.report_agent`、`pane.report_agent_session`、`pane.report_metadata`、`pane.clear_agent_authority`、`pane.release_agent` を `unsupported_runtime` で拒否します。

## 仕組み

エージェントの接続先ターミナル出力に状態を送ります。ルート報告には app 名と実際の状態を含めます。hc はそれを保存してスナップショット・イベントで公開し、ビューアー再接続時にも提供します。ライブのアタッチ上で明示的な有効な報告がなければ、Herdr は出力やローカル PID から推測せず unknown を表示します。

保存済み SSH 接続先のプログラムにクライアントの `HERDR_BIN_PATH`、`HERDR_SOCKET_PATH`、`HERDR_PANE_ID`、経路識別情報は自動注入しません。ローカル hc は Herdr の起動コンテキストを持てますが、状態の権威は与えず従来の報告は拒否します。クライアントソケットや従来の hook を hc 状態通路にしないでください。パスと環境は接続先マシンに属します。

## 状態を報告する

POSIX 接続先ターミナルで working を報告する例です:

```sh
printf '\033]7501;state=working:app=my-agent\007'
```

実際の変化時だけ報告します。`idle` は待機、`working` は作業、`blocked` は判断待ち、`done` は完了、`error` は失敗です。Herdr は接続先の `error` を blocked として扱い、フォーカスしても接続先の `done` を維持します。送信完了、タイマー経過、ビューアー接続だけで準備完了や完了を報告しないでください。

この静的な例は汎用エンコーダーではありません。エンコード、省略可能フィールド、レコード ID は hc の [API と状態の文書](https://github.com/herdrdev/herdr-core/blob/main/schema/README.md)を参照し、信頼できない文字列を制御シーケンスへ直接挿入しないでください。Herdr は別の状態ペイロードを定義しません。

## resume コマンドを報告する

hc ペインへ従来の `resume_argv` や `pane report-agent-session` を送らないでください。Herdr が復元するのは正確な恒久 core ID とターミナルアドレスであり、resume コマンドの実行、エージェントの再起動、代替シェルの作成はしません。

ユーザーが明示的に要求した新規起動は再接続とは別です。喪失・結果不明の起動を自動再試行しません。[セッション状態と復元](/ja/docs/session-state/)を参照してください。

## 終了時に解放する

ルート状態レコードを取り下げるには clear 報告を使います:

```sh
printf '\033]7501;state=clear\007'
```

状態クリアはプログラム終了ではありません。必要に応じて完了・失敗を正直に報告し、キャンセルや切断を成功に変えないでください。正常終了時の清理ではクラッシュや強制終了を扱えません。hc に従来の `pane release-agent` を呼ばないでください。

## エージェントの邪魔をしない

- 接続先の実際の状態だけを報告し、ビューアーのフォーカス・再接続を報告しません。
- 報告量を制限し、順序を維持します。再接続時に古い変化を新しい作業として再生しません。
- 報告がない場合にクライアント側 API、プロセス検索、画面分類へフォールバックしません。
- 状態は情報であり、ダイアログの承認権限でも、全バックグラウンド作業の終了証明でもありません。

## ソケットを直接使う

直接ランタイムへアクセスする統合は hc の公開 API とトランスポートを使ってください。`hc schema` が API を記述し、`hc connect` が SSH を含む標準入出力でプロトコルを運びます。hc のフレーミングは Herdr の私有ソケット・エンドポイント codec とは異なり、プロトコル世代も独立しています。

表示の自動化には別の Herdr [Socket API](/ja/docs/socket-api/)を使います。保存済み接続先への要求は検出済みホストインスタンスに固定し、切断後に実行済みかもしれない操作を再送しないでください。

## インテグレーションを確認する

継承した `--current` ではなく、対象の表示ホストが提供する明示的 ID を使います:

```bash
herdr pane get w1:p1
herdr agent list
```

使い捨ての名前付きセッションで実際の idle、working、blocked、done、clear を確認します。デタッチし、Herdr 表示ホストだけを再起動して、同じ hc バインディングと接続先プログラムが維持され、新規起動、入力再送、完了通知の再生がないことを確認してください。ビューアー再起動の代わりに hc を停止しないでください。
