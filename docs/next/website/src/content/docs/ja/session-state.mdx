Herdr は表示とレイアウトを保存します。**プログラムとターミナル状態は hc が所有**し、接続先はローカルまたは保存済み SSH マシンです。Herdr の復元はアタッチであり、プログラムの起動ではありません。

## 何が生き残るか

| ケース | hc プログラム | Herdr のレイアウトとターミナル表示 |
| --- | --- | --- |
| クライアントのデタッチ・終了 | 動き続ける | 同じ表示セッションへ再接続 |
| 表示ホストの停止・再起動 | Herdr は終了させない | 保存済みレイアウトと正確な hc バインディングを復元 |
| SSH 切断・接続先のオフライン | ビューアーの切断では終了しない | 復旧までレイアウトとバインディングを利用不可として保持 |
| 明示的なペインのクローズ | 明示的な hc close で終了させることがある | 終了または不在の確認後だけ削除 |
| 接続先 hc の停止、プログラム終了、接続先マシンの喪失 | 継続は保証しない | 保存済みペインを埋める代替プログラムは起動しない |

これは Herdr の動作に関する保証で、接続先マシンの耐久性の保証ではありません。hc を停止すると現在のプログラムは終了します。保存レコードは、生きたまま待機中のプログラムではありません。

## ライブ永続化

`ctrl+b q` でデタッチし、あとで再接続します:

```bash
herdr
```

`herdr server stop` と `herdr session stop <name>` は表示ホストを停止してビューアーをデタッチしますが、接続先プログラムは停止しません。明示的なペインのクローズは、正確にバインドされたプログラムの終了を hc に要求します。結果が不明な場合は成功とみなさず、ペインとバインディングを保持します。

## スナップショット復元

スナップショット形式 4 は、各ターミナルの恒久的な **hc core ID + 正規の接続先ローカルアドレス**と、ワークスペース、タブ、ペイン、レイアウト、cwd メタデータ、フォーカスを保存します。公開ペイン ID、PID、ソケットパス、プロファイル名、接続先セッション名ではバインディングを代用できません。

復元はローカルディレクトリの検査、履歴リプレイ、エージェントの resume、PTY インポートより先に保存済みバインディングへアタッチします。欠落、不正、オフライン、不一致の場合は、元のバインディングとレイアウトを利用不可として保持します。代替シェルの起動、別 core の同じアドレスへの取り込み、結果不明の起動の再試行、入力の再送は行いません。hc バインディングのない従来のペインもインポート・再起動しません。

Cwd とプロセス情報は接続先から取得します。リモートパスをクライアントのファイルシステムで検証せず、接続先がなくても同名のローカルディレクトリにフォールバックしません。固定した接続経路と復旧は[マシンへの接続](/ja/docs/connecting-machines/)を参照してください。

`session.json` を読み込めない、解析できない、新しい Herdr が必要な場合は理由をログに記録します。代替セッションの保存・削除前に元のバイト列を隣の `session-backups/` に保存し、パスを `persist.backup` として記録します。起動時に存在しなかったファイルも、最初の保存・削除前に再確認します。

読み込み失敗時の復旧用コピーは最新 3 個を保持し、新しいコピーを安全に保存してから古いコピーを削除します。コピーに失敗すると、自動保存・終了時とも元のファイルを変更せず記録し、次の保存要求で再試行します。コピーは自動復元されず、ペイン画面履歴も含みません。

## シャットダウンとスナップショットからの復旧

systemd-logind を使う Linux では、Herdr はホストの終了前に表示状態を保存するため、上限付きの遅延を要求します。接続先の終了、強制終了、電源断を越えて hc プログラムを維持する機能ではありません。logind がない環境では利用できません。

`session.json` の隣の `session-snapshots/` に最大 48 個のレイアウトを保存します。最初の保存は直ちにコピーし、その後の保存・削除では以前のレイアウトを最大 15 分に 1 回コピーします。同じ内容は重複保存せず、間隔は表示ホストの再起動後も維持されます。直近の変更は含まれないことがあります。

復旧の自動通知や古いスナップショットの自動復元はありません。レイアウトまたは読み込み失敗時のコピーを復旧するには:

1. `herdr session list --json` で対象セッションのディレクトリを確認します。
2. 表示ホストを停止します。デフォルトは `herdr server stop`、名前付きは `herdr session stop <name>` です。レイアウト復旧のためだけに hc を停止しないでください。
3. 現在の `session.json` を別に保存し、`session-snapshots/` または `session-backups/` の選んだファイルを `session.json` にコピーします。更新日時でコピー時刻を確認できます。
4. 表示セッションを再起動します。元の接続先で依然有効なバインディングだけにアタッチできます。

スナップショットには非公開のレイアウト、パス、バインディング、メタデータが含まれますが、実行中のプロセスは含まれません。古いレイアウトの復旧で終了済みプログラムが復活することはありません。コピー失敗はログに記録しますが、主セッションの保存を妨げません。

## ペイン画面履歴のリプレイ

hc アタッチは hc からターミナル状態を取得します。従来の `[experimental] pane_history` リプレイで hc アタッチを再構築することはなく、履歴からプログラムやエージェントの生存を判断することもありません。

PTY を所有する古い Herdr サーバーは、この設定で `session-history.json` を保存できます。機密性のあるターミナル履歴として扱ってください。hc のインポート・復旧手段ではありません。

## エージェントネイティブのセッション復元

hc 復元でエージェントの resume コマンドは呼び出しません。`[session] resume_agents_on_restore` と `startup_per_agent_delay_ms` は従来のエージェント再起動経路の設定で、有効にしても hc ペインを起動・再開しません。

生きているエージェントは元の接続先プログラムのままです。終了・欠落したエージェントは自動で置き換えません。状態には hc の明示的な報告が必要で、保存名、セッション参照、画面、起動意図は準備完了の証拠ではありません。[エージェント](/ja/docs/agents/)と[エージェントに Herdr 対応を追加する](/ja/docs/add-herdr-support/)を参照してください。

## ライブハンドオフ

hc アタッチは再接続し、PTY 所有権を移しません。Live-PTY インポートや `--handoff` は hc の移行・復旧経路ではありません。従来のプログラムを取り込まないため、明示的に切り替えを準備するまでは元のサーバーを維持してください。

明示的な従来の `herdr --remote` と互換性のある古い PTY サーバーには別の更新・ハンドオフ動作があります。[永続化とリモートアクセス](/ja/docs/persistence-remote/)を参照してください。Herdr エンドポイント世代 1 と hc のプロトコル世代は独立した互換性契約です。

切断後にクエリをやり直すことはできますが、プログラム起動、入力送信、その他の副作用が発生した可能性のある要求は自動で再試行しないでください。結果不明は再送の許可ではありません。
