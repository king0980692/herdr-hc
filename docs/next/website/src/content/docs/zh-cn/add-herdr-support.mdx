title: 为你的智能体添加 Herdr 支持
description: 通过源端 hc 与 OSC 7501 上报智能体状态，不依赖客户端本地 hook 或自动恢复进程。
---

hc 窗格使用 **hc 的程序状态协议 OSC 7501** 上报。hc 拥有事实，Herdr 展示这些事实，并用实时上报的转换驱动等待和通知。不需要 Herdr 进程名或屏幕规则来判定状态。

旧版 Herdr CLI／socket 上报和 resume 集成是独立的旧协议。hc 窗格以 `unsupported_runtime` 拒绝 `pane.report_agent`、`pane.report_agent_session`、`pane.report_metadata`、`pane.clear_agent_authority` 和 `pane.release_agent`。

## 工作方式

在智能体的源端终端输出中发送状态。根报告包含 app 名称和真实状态。hc 保存报告，通过快照／事件公开，并在查看端重连时提供。实时附加上没有明确且可用的报告时，Herdr 显示 unknown，不根据输出或本地 PID 猜测。

已保存 SSH 源端程序不会自动获得客户端的 `HERDR_BIN_PATH`、`HERDR_SOCKET_PATH`、`HERDR_PANE_ID` 或路由身份。本地 hc 启动可以携带 Herdr 上下文，但这些变量不赋予状态权威，旧上报方法仍被拒绝。不要寻找客户端 socket 或安装旧 hook 作为 hc 状态通道。路径和环境属于源机器。

## 上报状态

例如在 POSIX 源端终端上发送 working 报告：

```sh
printf '\033]7501;state=working:app=my-agent\007'
```

只在真实变化发生时发送：`idle` 表示空闲、`working` 表示工作、`blocked` 表示需要决定、`done` 表示完成、`error` 表示失败。Herdr 将源端 `error` 映射为 blocked，聚焦后仍保留源端 `done`。不要仅因命令已提交、定时器到期或查看端连接就报告就绪或完成。

此静态例子不是通用编码器。编码、可选字段及记录 ID 见 hc 的 [API 与状态文档](https://github.com/herdrdev/herdr-core/blob/main/schema/README.md)。不要把不可信文本直接插入终端控制序列。Herdr 不定义另一套状态载荷。

## 上报恢复命令

不要为 hc 窗格发送旧版 `resume_argv` 或 `pane report-agent-session`。Herdr 恢复的是精确的永久 core ID 和终端地址，绝不运行 resume 命令、重启智能体或创建替代 shell。

用户明确要求的新启动与重连不同。丢失或结果不确定的启动不能自动重试。见[会话状态与恢复](/zh-cn/docs/session-state/)。

## 退出时释放

使用协议的 clear 报告撤销根状态记录：

```sh
printf '\033]7501;state=clear\007'
```

清除状态不是终止程序。适当时应如实报告完成或失败，不把取消或断线当作成功。正常退出时的清理不能覆盖崩溃或强制终止。不要为 hc 调用旧 `pane release-agent` 端点。

## 不要拖慢智能体

- 只上报真实源端状态，不上报查看端本地聚焦或重连事件。
- 限制报告量并保持顺序，重连后不把旧转换重放成新工作。
- 报告不可用时，不回退到客户端本地 API、进程查询或屏幕分类。
- 状态是信息，不是批准对话框的授权，也不是所有后台任务已结束的证明。

## 直接使用套接字

需要直接访问运行时的集成应使用 hc 的公开 API 和传输。`hc schema` 描述 API；`hc connect` 通过标准输入／输出承载协议，包括 SSH。hc 分帧不是 Herdr 私有 socket 或端点 codec，两者的协议代际互相独立。

呈现自动化仍使用独立的 Herdr [Socket API](/zh-cn/docs/socket-api/)。已保存源端请求应固定到发现的主机实例，断线后绝不重放可能已生效的操作。

## 检查你的集成

使用目标呈现主机提供的明确 ID，不依赖继承的 `--current` 身份：

```bash
herdr pane get w1:p1
herdr agent list
```

在一次性命名会话中验证真实的 idle、working、blocked、done 和 clear 转换。分离并仅重启 Herdr 呈现主机，确认相同 hc 绑定和源端程序仍存活，没有新启动、输入重放或完成通知重放。不要用停止 hc 来代替重启查看端。
