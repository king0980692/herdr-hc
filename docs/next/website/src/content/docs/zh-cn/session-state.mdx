---

Herdr 保存呈现与布局。**hc 拥有程序和终端状态**，无论源端在本地还是已保存的 SSH 机器上。恢复 Herdr 是附加操作，不是启动程序。

## 什么能保留下来

| 场景 | hc 程序 | Herdr 布局与终端视图 |
| --- | --- | --- |
| 客户端分离或退出 | 继续运行 | 重新连接同一呈现会话 |
| 呈现主机停止或重启 | 不会被 Herdr 终止 | 恢复保存的布局，附加精确 hc 绑定 |
| SSH 中断或源端离线 | 不会因查看端断开而终止 | 保留布局和绑定，恢复前显示不可用 |
| 明确关闭窗格 | 可以通过明确的 hc close 终止 | 只在确认终止或不存在后移除 |
| 观察到程序退出（`keep=false`、hc 原因为 `exited`） | 已结束 | 移除窗格及空标签页/工作区，绝不启动替代程序 |
| 源端 hc 停止或源机器丢失 | 不保证继续运行 | 绝不启动替代程序填补保存的窗格 |

智能体上报 `done` 状态不等于程序退出。保留型终端，以及在程序已经结束后恢复的历史绑定，仍留在布局中。源端或传输连接丢失绝不会被当作 shell 正常退出。

这些保证约束 Herdr 的行为，不保证源机器的持久性。停止 hc 会结束其当前程序；保存的记录不等于仍然存活的停放程序。

## 实时持久化

用 `ctrl+b q` 分离，之后重新连接：

```bash
herdr
```

`herdr server stop` 和 `herdr session stop <name>` 停止呈现主机并分离查看端，不停止源端程序。明确关闭窗格不同：它要求 hc 终止精确绑定的程序。关闭结果不确定时保留窗格和绑定，不假设成功。

## 快照恢复

快照版本 4 为每个终端保存永久的 **hc core ID + 规范源端本地地址**，以及工作区、标签页、窗格、布局、cwd 元数据和焦点。公共窗格 ID、PID、socket 路径、配置标签和源会话名都不能替代此绑定。

恢复会先附加保存的绑定，再考虑本地目录检查、历史回放、智能体恢复或 PTY 导入。缺失、格式错误、离线或不匹配的绑定保留布局和原始绑定，并显示不可用。Herdr 不替换 shell、不接管其他 core 中同地址的终端、不重试结果不确定的启动、不重放输入。没有 hc 绑定的旧窗格不会被导入或重启。

Cwd 和进程事实来自源端。远程路径不会在客户端文件系统上验证；源端缺失也不会回退到同名本地目录。固定源路由与恢复规则见[连接机器](/zh-cn/docs/connecting-machines/)。

如果无法读取或解析 `session.json`，或文件需要更新的 Herdr 版本，Herdr 会记录原因。在保存或清除替代会话之前，将原始字节保存在 `session.json` 旁的 `session-backups/`，并以 `persist.backup` 记录路径。启动时不存在的文件也会在首次保存或清除前再次检查。

Herdr 保留最新的三个加载失败恢复副本，只有在新副本安全写入后才删除旧副本。保存副本失败时，自动保存和退出保存都保留原始文件并记录错误，在下次保存请求时重试。副本不会自动恢复，也不包含窗格屏幕历史。

## 关机与快照恢复

在使用 systemd-logind 的 Linux 上，Herdr 会请求有界延迟，在主机关机前保存呈现状态。这不能让 hc 程序跨源端关机、强制终止或断电继续运行；没有 logind 时不提供此保护。

Herdr 在 `session.json` 旁的 `session-snapshots/` 中保留最多 48 个布局快照。首次保存的布局立即复制；之后的保存或清除最多每 15 分钟复制一次旧布局。不重复保存相同内容，间隔在呈现主机重启后仍有效。最近的修改可能尚未包含在内。

不会自动提示恢复，也不会自动恢复旧快照。恢复布局或加载失败副本的方法：

1. 用 `herdr session list --json` 找到会话目录。
2. 停止呈现主机：默认会话用 `herdr server stop`，命名会话用 `herdr session stop <name>`。不要仅为恢复布局而停止 hc。
3. 另存当前 `session.json`，再将 `session-snapshots/` 或 `session-backups/` 中选定的文件复制到 `session.json`。修改时间表示复制时间。
4. 重新启动呈现会话。只有在原源端仍有效的绑定才能附加。

快照包含私密的布局、路径、绑定和元数据，不包含运行中的进程。恢复旧布局不会复活已退出的程序。快照写入失败会记录日志，但不会阻止主会话保存。

## 窗格屏幕历史回放

hc 附加从 hc 获取终端状态。旧版 `[experimental] pane_history` 回放路径不用于重建 hc 附加，也不能证明程序或智能体仍然存活。

拥有 PTY 的旧版 Herdr 服务器可以在启用此选项后保存 `session-history.json`。请将其视为敏感终端历史；它不是 hc 导入或恢复机制。

## 智能体原生会话恢复

hc 恢复绝不调用智能体的 resume 命令。`[session] resume_agents_on_restore` 和 `startup_per_agent_delay_ms` 属于旧版智能体重启路径；开启它们也不会启动或恢复 hc 窗格。

仍存活的智能体保持为原始源端程序；已退出或缺失的智能体不会自动替换。状态必须由 hc 明确上报，保存的名称、会话引用、屏幕内容和启动意图都不是就绪证据。参阅[智能体](/zh-cn/docs/agents/)与[为你的智能体添加 Herdr 支持](/zh-cn/docs/add-herdr-support/)。

## 实时交接

hc 附加通过重连恢复，不转移 PTY 所有权。Live-PTY 导入和 `--handoff` 都不是 hc 迁移或恢复路径。现有旧程序不会被接管；在明确安排切换之前，请保留原服务器运行。

明确使用的旧版 `herdr --remote` 路径和兼容的旧 PTY 服务器有独立的更新／handoff 行为，见[持久化与远程访问](/zh-cn/docs/persistence-remote/)。Herdr 端点第 1 代与 hc 协议代际是独立的兼容性约定。

断线后可以重新查询，但不能自动重试可能已经启动程序、发送输入或产生其他副作用的请求。结果不确定不是重放许可。
