---
title: Add Herdr support to your agent
description: Report agent status through source hc and OSC 7501, without client-local hooks or automatic process resume.
---

For hc-owned panes, report through **hc's Program Status Protocol, OSC 7501**. hc owns the facts; Herdr displays them and uses live reported transitions for waits and notifications. No Herdr process-name or screen rule is needed for status.

The old Herdr CLI/socket reporting and resume integration is a separate legacy contract. hc-owned panes reject `pane.report_agent`, `pane.report_agent_session`, `pane.report_metadata`, `pane.clear_agent_authority`, and `pane.release_agent` with `unsupported_runtime`.

## How it works

Emit status on the agent's source terminal output. A root report names the app and its actual state. hc stores it, exposes it through snapshots/events, and supplies it when a viewer reconnects. Without an explicit usable report on a live attachment, Herdr shows unknown rather than guessing from output or a local PID.

Saved SSH source programs are not given the client's `HERDR_BIN_PATH`, `HERDR_SOCKET_PATH`, `HERDR_PANE_ID`, or routing identity automatically. Local hc launches may carry Herdr launch context, but those variables grant no status authority: the legacy report methods are still rejected. Do not discover a client socket or install a legacy hook as an hc status transport. Source paths and environment belong to the source machine.

## Report state

For example, on a POSIX source terminal, emit a working report:

```sh
printf '\033]7501;state=working:app=my-agent\007'
```

Emit the real transition when it happens: `idle` for idle, `working` for work, `blocked` for a required decision, `done` for completion, or `error` for failure. Herdr maps source `error` to blocked and preserves source `done` after focus. Do not report readiness or completion merely because a command was submitted, a timer elapsed, or a viewer connected.

This static example is not a general encoder. Use hc's [API and status documentation](https://github.com/herdrdev/herdr-core/blob/main/schema/README.md) for encoding, optional fields, and record IDs; do not interpolate untrusted text into terminal controls. Herdr does not define an alternative status payload.

## Report the resume command

Do not send a legacy `resume_argv` or `pane report-agent-session` report for an hc pane. Herdr restores the exact permanent core ID and terminal address; it never runs your resume command, restarts your agent, or creates a replacement shell.

An explicit user-requested new launch is separate from reconnecting. Lost or uncertain launches must not be retried automatically. See [Session state and restore](/docs/session-state/).

## Release on exit

To withdraw a root status record, use the protocol's clear report:

```sh
printf '\033]7501;state=clear\007'
```

Clearing status is not program termination. Report truthful completion or failure when appropriate; do not turn cancellation or lost connectivity into success. Cleanup on graceful exit cannot cover a crash or forced termination. Do not call the legacy `pane release-agent` endpoint for hc.

## Keep it out of the way

- Emit reports only for actual source state, not viewer-local focus or reconnect events.
- Keep status output bounded and ordered. Do not replay old transitions as new work after reconnect.
- Never fall back to a client-local API, process lookup, or screen classifier when a report is unavailable.
- Treat status as information, not permission to approve a dialog or proof that all background jobs ended.

## Use the socket directly

Use hc's published API and transport if your integration needs direct runtime access. `hc schema` describes that API; `hc connect` carries its protocol over standard input/output, including SSH. hc framing is not Herdr's private socket or endpoint codec. Their protocol generations are independent.

For presentation automation, Herdr's [Socket API](/docs/socket-api/) remains separate. Pin saved-source requests to the discovered host instance and never replay a possibly effective action after connection loss.

## Check your integration

Use explicit IDs from the intended presentation host, not an inherited `--current` identity:

```bash
herdr pane get w1:p1
herdr agent list
```

In a disposable named session, verify real idle, working, blocked, done, and clear transitions. Detach and restart only the Herdr presentation host, then confirm that the same hc binding and source program survive, with no new launch, input replay, or completion notification replay. Do not stop hc as a substitute for restarting the viewer.
