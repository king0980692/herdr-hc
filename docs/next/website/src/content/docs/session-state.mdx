---
title: Session state and restore
description: Understand hc program ownership, exact-binding recovery, layout snapshots, and the limits of legacy restore and handoff.
---

Herdr saves presentation and layout. **hc owns programs and terminal state**, locally or on a saved SSH source. Restoring Herdr is an attachment operation, not a process launch.

## What survives

| Case | hc programs | Herdr layout and terminal view |
| --- | --- | --- |
| Client detach or exit | Keep running | Reattach to the same presentation session |
| Presentation host stop or restart | Are not terminated by Herdr | Restore saved layout and attach exact hc bindings |
| SSH loss or offline source | Are not terminated by the viewer disconnect | Keep layout and bindings unavailable until recovery |
| Explicit pane close | May be terminated by an explicit hc close | Remove only after termination or absence is confirmed |
| Source hc stop, program exit, or source machine loss | Continuation is not guaranteed | Never launch a replacement to fill the saved pane |

These guarantees concern Herdr's actions, not source-machine durability. Stopping hc ends its current programs; a saved record is not a live parked program.

## Live persistence

Detach with `ctrl+b q`. Reattach later:

```bash
herdr
```

`herdr server stop` and `herdr session stop <name>` stop the presentation host and detach its viewers, not the source programs. Explicit pane close is different: it asks hc to terminate the exact bound program. An uncertain close keeps the pane and binding instead of assuming success.

## Snapshot restore

Snapshot version 4 stores each terminal's permanent **hc core ID + canonical source-local address**, alongside workspaces, tabs, panes, layout, cwd metadata, and focus. Public pane IDs, PIDs, socket paths, profile labels, and source session names are not substitutes for that binding.

Restore attaches the saved binding before any local directory checks, history replay, agent resume, or PTY import. Missing, malformed, offline, or mismatched bindings retain their layout and raw binding as unavailable. Herdr does not substitute a shell, adopt another core's terminal at the same address, retry an uncertain launch, or replay input. Legacy panes without hc bindings are not imported or restarted.

Cwd and process facts come from the source. A remote path is not validated against the client's filesystem, and a missing source never falls back to a same-named local directory. See [Connecting machines](/docs/connecting-machines/) for pinned source routes and recovery.

If `session.json` cannot be read or parsed, or requires a newer Herdr version, Herdr logs why loading failed. Before saving or clearing the replacement session, it preserves the original bytes in `session-backups/` beside `session.json` and logs the path as `persist.backup`. A file missing at startup is checked again before the first save or clear.

Herdr retains the three most recent failed-load recovery copies, pruning older copies only after a new copy is safely written. If preservation fails, autosave and shutdown leave the original untouched and log the failure; the next save request retries preservation. Copies are never restored automatically and do not include pane screen history.

## Shutdown and snapshot recovery

On Linux with systemd-logind, Herdr requests a bounded delay to save presentation state before host shutdown. This does not keep hc programs alive through source shutdown, forced termination, or power loss. It is unavailable without logind.

Herdr keeps up to 48 layout snapshots in `session-snapshots/` beside `session.json`. The first saved layout is copied immediately. Later saves or clears can copy the previous layout at most once every 15 minutes. Identical layouts are not duplicated, and the interval survives presentation host restarts. Recent changes may not yet be included.

There are no automatic recovery prompts or automatic restoration of older snapshots. To recover a layout or a failed-load backup:

1. Find the affected session directory with `herdr session list --json`.
2. Stop its presentation host: `herdr server stop`, or `herdr session stop <name>` for a named session. Do not stop hc merely to recover a layout.
3. Keep a copy of the current `session.json`, then copy the chosen file from `session-snapshots/` or `session-backups/` over `session.json`. Modification times identify when copies were taken.
4. Start the presentation session again. Only bindings still valid on the original source can attach.

Snapshots contain private layout, paths, bindings, and metadata, not running processes. Recovering an older layout does not resurrect an exited program. A snapshot-write failure is logged but does not prevent the primary session from saving.

## Pane screen history replay

hc attachments obtain terminal state from hc. The legacy `[experimental] pane_history` replay path is not used to reconstruct an hc attachment and never proves that a program or agent is alive.

Older Herdr-owned PTY servers can retain `session-history.json` when that option is enabled. Treat those files as sensitive terminal history. They are not an hc import or recovery mechanism.

## Native agent session restore

hc restore never invokes an agent's resume command. `[session] resume_agents_on_restore` and `startup_per_agent_delay_ms` belong to the legacy agent-relaunch path; enabling them does not launch or resume hc-owned panes.

A surviving agent remains the original source program. An exited or missing agent is not replaced automatically. Status requires explicit hc reports; saved names, session references, screen contents, and launch intent are not readiness evidence. See [Agents](/docs/agents/) and [Add Herdr support to your agent](/docs/add-herdr-support/).

## Live handoff

hc attachments reconnect; they do not transfer PTY ownership. Live-PTY import and `--handoff` are not hc migration or recovery paths. Existing legacy programs are not adopted: keep their original server running until you explicitly arrange a cutover.

The explicit legacy `herdr --remote` path and older compatible Herdr-owned PTY servers have separate update/handoff behavior; see [Persistence and remote access](/docs/persistence-remote/). Herdr endpoint generation 1 and hc's protocol generation are independent compatibility contracts.

After a disconnect, queries may be made again, but do not automatically retry a request that could have launched a program, sent input, or otherwise taken effect. An uncertain outcome is not permission to replay it.
