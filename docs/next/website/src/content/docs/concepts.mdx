title: Concepts
description: Understand Herdr workspaces, tabs, panes, agents, sessions, and modes.
---

Herdr is a terminal workspace manager. hc owns real terminal programs and state; Herdr adds presentation, layout, and input routing around exact source bindings.

## Workspace

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

A workspace owns tabs and panes. Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane presents an hc terminal bound by permanent core ID and canonical source-local address. Herdr renders its output and routes input without owning a local child process. Client detach preserves the binding; explicit close may terminate only that exact program after confirmation.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

## Mouse UI

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

## Agent

For hc-owned panes, an agent's identity and semantic state come from explicit source hc status reports, including OSC 7501. Herdr does not infer status from screens, a client-local PID, legacy hooks, or a pending launch. Without a current report on a live attachment, status is `unknown`.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The source explicitly reports completion. |
| `idle` | The source explicitly reports idle. |
| `unknown` | A current usable source status is unavailable or unrecognized. |

Viewing or focusing an hc pane does not change source `done` to `idle`. Client-local attention markers are presentation, not source state. Only live reported transitions notify; reconnecting does not replay completion notifications. A status is not proof that every background job has finished or authorization to approve a prompt.

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named Herdr sessions are separate presentation namespaces, not hc core identities:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions for separate presentation panes, sockets, and saved layout. Programs remain owned by their hc source; changing a Herdr session name does not retarget their bindings.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The Herdr host owns layout and presentation. The client is its terminal UI. hc independently owns programs, terminal state, cwd, and reported status. Saved SSH machines use local Herdr presentation connected to source hc over SSH, not a remote Herdr renderer.

With one attached client, all tabs follow its size as before. With multiple clients, each can view its own workspace and tab. Different viewed tabs follow their respective clients; when clients view the same tab, the last one to focus, select, or interact with it controls that tab's pane sizes.

Detach the client with `ctrl+b q`. The server and agents continue running.

To stop only the presentation host, leaving hc programs untouched:

```bash
herdr server stop
```

To terminate a bound program, explicitly close its pane. An uncertain close retains the pane and binding. See [Session state and restore](/docs/session-state/).

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. See [Keyboard](/docs/keyboard/) if the prefix idea is new to you.
