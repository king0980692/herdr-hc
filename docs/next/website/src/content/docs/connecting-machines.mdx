description: Keep Herdr presentation local while hc owns programs and terminals on saved SSH machines.

The hc-backed build reads the **shared default hc machine registry**; it does not copy those machines into a second SSH catalog. Switch between their workspaces and Local in one Herdr window. **Herdr renders locally; hc owns the remote programs, terminal state, and reported agent status.** Saved-machine setup does not install, start, replace, or render through remote Herdr.

There are two independent connections: the client connects to a local presentation host, and that host connects to hc over SSH. A working presentation connection does not by itself mean hc is reachable. Unavailable panes keep their saved identity and layout; they do not become replacement shells.

## Shared hc machines

Inspect and manage the common inventory with hc (`hc machine ls --json`). Herdr refreshes it in the background, outside pane rendering. Names are display labels; a source is identified by its permanent owner core ID and the registry core ID. Renaming a machine does not change bindings, while a replaced owner, registry, or route cannot silently take over an old layout.

For a machine with no saved native layout, its existing **live, owner-local programs each become a tab**. This attaches views, not new shells, and does not import another application's PTYs or layouts. Saved native layouts are restored unchanged; finished history is not imported as live. An empty remote source stays empty until you explicitly create a workspace. Explicit pane close terminates that exact shared program; quitting or losing Herdr only detaches.

Direct SSH machines are supported. Provider-command (`via`) transports fail closed rather than being reinterpreted as SSH. Source status, input leadership, and resize behavior must be compatible with the installed hc; a connection alone does not qualify multi-viewer behavior.

The saved-profile commands below remain for **explicit legacy/custom sources**, including a side-by-side `--hc-path`. They are not required for machines already in the common registry and do not edit that registry.

## Before you connect

Verify ordinary SSH access first:

```bash
ssh workbox
```

`workbox` may be an SSH configuration alias. Targets such as `ssh://you@server:2222` are also accepted. Install a compatible `hc` on the source machine before adding it. Herdr checks the hc API; it does not offer a remote Herdr installer or silently update hc.

The current source launch path uses a POSIX shell and source-side `/usr/bin/env`. macOS and Linux source paths are covered by native smoke tests; Windows source launch is not yet validated. Authentication and host-key approval remain OpenSSH's responsibility. Load a passphrase-protected key with `ssh-add` before background connections need it.

## Add a machine

```bash
herdr machine add workbox
herdr machine add workbox --remote-session agents --label "Build machine"
# Optional: select a side-by-side hc executable on the source, then use the normal UI.
herdr machine add workbox --remote-session agents --hc-path /home/user/.local/opt/hc/bin/hc
herdr
```

`--remote-session` selects an **hc source session**, not a remote Herdr session. Without it, setup uses `default`; it does not discover remote Herdr sessions. The default label is the host, or `host/session` for a named session. Use `--label` when that name is already taken.

`--hc-path` is an optional absolute **source-local executable path**, not a shell command or a local Mac/Linux path. When omitted, Herdr uses `hc` on the remote PATH. The selected path is saved and reused by status checks, reconnects, and the TUI. A missing or incompatible custom executable fails without falling back to another hc. Profiles using this field require an updated local Herdr; update older clients and presentation hosts before sharing such a catalog.

Setup verifies installed hc over SSH, then saves the profile. It does not create a shell, adopt arbitrary existing hc terminals, or restart an existing program. A new profile has an empty local presentation until you explicitly create a workspace. Reopening a profile restores only terminals with saved hc bindings.

Each profile has an opaque ID and an isolated local presentation session named `hc-<profile-id>`. Its presentation host can outlive the client. Closing the client detaches; it does not terminate the source programs.

Run `herdr` to open the UI. Enabled machines appear through the existing machine sidebar and connect independently. Selecting another machine does not move or restart programs.

## Switch between machines

Choose a machine or one of its workspaces in the sidebar. The selected machine receives pane input and size updates. Other connected machines continue updating their metadata without streaming hidden pane screens.

Click a machine's arrow to collapse or expand its workspace list without switching. For keyboard navigation, press `prefix+w`, highlight a workspace, and press Enter to activate it. Esc or the prefix key cancels. Highlighting alone does not retarget pane, tab, workspace, or custom-command shortcuts.

Local remains independent of saved-machine failures. A stalled source cannot take selection away from the machine you are using. Multiple clients may still select different tabs; see [Client and server](/docs/concepts/#client-and-server).

## Reconnect and close safely

A source transport interruption detaches viewers, not programs. Herdr reconnects the transport, then asynchronously attaches each saved terminal by its **permanent hc core ID and canonical terminal address**. Public workspace, tab, and pane IDs remain presentation identities, not hc addresses.

Recovery never retries an uncertain `terminal.run`, replays input, resumes an agent, imports a legacy PTY, or substitutes another terminal with the same source-local address. A missing terminal, wrong core, malformed binding, or offline source stays unavailable with its original layout and binding intact. Programs without explicitly reported hc status remain unknown; Herdr does not infer their state from the screen or a local PID.

Source retries start at 500 ms and back off to at most 30 seconds. A minute of healthy connectivity resets the backoff. Attachment attempts are separately bounded and cancellable. The existing client-to-presentation-host reconnect policy is independent of this source retry loop.

Explicit pane, tab, workspace, or popup close may terminate the exact bound hc program. The layout and binding are removed only after hc confirms termination or validly confirms absence. An offline or ambiguous close retains them and reports failure. Closing the last pane never creates a replacement shell.

## Rename, disable, or remove

Read IDs from the catalog rather than deriving them from labels or hostnames:

```bash
herdr machine list
herdr machine list --json
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id>
```

Renaming changes the label, not program identity. Disabling keeps the profile; removing forgets it. Both detach that source without killing its hc programs. They do not affect other machines. Removing or disabling the selected machine returns the client to Local, or to Local's unavailable/reconnecting state instead of selecting an unrelated remote machine.

A changed route (including the hc executable path, even when it reaches the same core) or permanent core ID retires the old local source host. A fresh host has a new instance identity; stale requests are rejected rather than forwarded to its replacement. Retargeting never turns an old `t1` binding into authority over another core's `t1`.

## Connection problems

```bash
herdr machine status [<label-or-id>] [--json]
herdr machine reconnect <label-or-id>
```

Status checks installed hc noninteractively. Reconnect completes supported native SSH authentication and verifies hc; it does not install or update Herdr or hc. Background connections require known host keys and never answer authentication or host-key prompts. They reuse the existing managed SSH authentication transport when enabled; after a failed read-only connection, repair can retire only a proven stale, still-current managed listener. This does not stop existing SSH sessions or hc programs. Click an error/reconnect badge to retry and inspect the current notice. Other machines remain usable.

If hc is missing or incompatible, update hc explicitly on the source. If the local presentation host lacks the required API, update **local Herdr**. Do not replace a remote Herdr server to repair a saved hc connection. Stopping a local presentation host detaches its viewers; hc programs remain on the source.

An unreadable or invalid profile catalog must be repaired before activating a changed route. Existing client connections retain their independently fenced lifecycle; a profile error is not authority to stop an unrelated server.

## Source paths and available operations

Implicit shells use the source's `SHELL` (or `/bin/sh`), not the client's shell path. Default home/current-directory behavior is resolved on the source; follow-directory behavior uses hc-reported cwd. Explicit paths and argv are source values and are not expanded using the client's home directory.

Terminal commands run through hc. Herdr does not copy executables, configuration, command plugins, or secrets to the source. Source programs do not receive the local presentation host's API socket, executable path, pane identity, or local SSH-agent proxy path; the source's own SSH-agent environment is preserved. Use source-side `hc` for its runtime, or machine-targeted Herdr commands from the local client. Missing commands fail visibly. Source Git discovery and worktree filesystem operations are currently unavailable through this adapter: they are rejected or omitted, never implemented by touching a similarly named local path.

Workspace, tab, pane IDs, and agent names are scoped to their presentation host. Two profiles may both contain `w1:p1`. Selecting a machine in the UI does not retarget CLI commands in an existing pane. For automation, pass the same machine prefix on each command:

```bash
herdr --machine <label-or-id> agent list
herdr --machine <label-or-id> workspace list
```

The CLI does not require an open TUI. It resolves the saved profile to its local source host and pins subsequent requests to that host instance. A host restart is an error for an already resolved request, not permission to rediscover a target and replay a mutation.

## Saved data and legacy programs

The catalog contains only profile ID, label, SSH target, hc session, and enabled state. It stores no passwords, private keys, or SSH control sockets. Bindings and presentation layout are saved separately. Snapshot version 4 prevents an older Herdr from treating an hc binding as legacy relaunch instructions.

Existing legacy Herdr programs are **not imported, restarted, or adopted**. hc has no published live-PTY import API. Keep the old server running until you explicitly arrange a cutover; changing a saved-machine profile is not a migration of its old Herdr terminals. Live PTY handoff and hc worktree removal through legacy process management are unsupported.
